# DV11 - Plan Journal

Append-only log of the 5-agent role-less open-ended audit loop for the DV11 MobileTabPager swipe-preview height fix. Each round: 5 independent auditors examine `docs/DV11-Plan.md` against the real codebase under an open-ended mandate (find ANY defect; do NOT limit scrutiny to the plan's own concerns); loop until 5/5 unconditional PASS (DV04/DV10 pattern). Owner-locked requirements (§3) are not relitigated.

## Round 1 - not 5/5 PASS → revised (v1 screen-height freeze → v2 track-dest)

Full detail: `DV11-Audit-R1.md`. 5/5 FAIL, all high confidence, organic clean.

Convergent blockers:

- **B1 (5/5).** The screen-height freeze (`freezeHeight = innerHeight - headerHeight`) makes the regression e2e FAIL, not pass. The e2e asserts `duringForward.vpHeight === landedMessages.vpHeight` where `landed*` is measured at rest (content height, `panelHeights[activeIndex]`: 646 / 2563), not screen height. Under the freeze `duringForward.vpHeight ≈ 795`. Two auditors ran the e2e to confirm the numbers. The "3 assertions flip green unchanged" claim was mathematically false.
- **B2 (5/5).** No release hook exists in MobileTabPager (no `afterNavigate`, no `onTrackTransitionEnd`, no `transitionend`); `pendingCancel` is GPL-only (`GesturePageLayout.svelte:271`). The release machinery v1 depended on does not exist in the target file.
- **B3 (2/5 blocking + convergent).** The freeze corrupts `panelHeights`: `measureTab`'s ResizeObserver (`:314-322`) writes `panelHeights[index] = section.offsetHeight`; setting each section to `height: ${freezeHeight}px` overwrites all `panelHeights` to screen height, so rest-mode `viewportHeight` is pinned to screen height on release and tall panels are clipped at rest. v1 §4.5's "unchanged" claim was causally backwards.

Convergent majors: freeze entry non-atomic / no rAF re-apply (the `$effect` flush defers style past the first revealed frame; the GPL `:286-320` precedent uses rAF); destScroll uses the wrong store (the `(tabs)` layout restores via SvelteKit `snapshot` + `getListScrollStore`, not `pageScrollStore`; tab roots carry no hash so the "three-tier chain" is dead in scope); paint/padding rationale cites `fixed-viewport`-gated CSS that never applies to the pager; conflicting commit `scrollTo`, header-hidden-at-start, `neighborOffset` re-sync, mid-freeze dest scroll; `setScrollContainer`/`setOverride` conflation.

Revision decision (v2): replace the screen-height freeze with a **track-dest viewport** derivation. `viewportHeight = panelHeights[inSwipe ? destIndex : activeIndex]` - the sections stay at natural height (B3 dissolves: `measureTab` unaffected), the swipe-time value is the dest's own `panelHeights` value so it equals the landed value exactly (B1 dissolves), and the derivation reverts automatically when the swipe ends with `activeIndex === destIndex` (B2 dissolves: no release hook). Source scroll-capture (`translateY(-sourceScrollY)` + rAF re-apply + window held at 0) prevents a scrolled source from flashing to top. No `fixed-viewport`, no per-panel internal-scroll, no `scrollChrome` swap. dest-scroll fidelity deferred to the `(tabs)` snapshot mechanism (known limitation).

Verified-TRUE facts carried forward: `viewportHeight = panelHeights[activeIndex]` (`:302`) + `overflow-hidden` (`:364`); `activeIndex` changes only in `switchTo/switchBackward`; `swipeMove` writes only `dragOffset`; `measureTab` observes section offsetHeight into `panelHeights`; the three sections are `w-1/3 shrink-0 p-3` with `data-tab-panel`, no `bind:this`; MobileTabPager has no `afterNavigate`/`onTrackTransitionEnd`; `pendingCancel` is GPL-only; `html.fixed-viewport` added only by `GesturePageLayout.svelte:866`; `(tabs)/+layout.svelte:48-67/105-108` restores scroll via SvelteKit `snapshot` + `getListScrollStore` (not `pageScrollStore`); `swipeMove:174-177` deep-preview sub-branch sets `dragOffset` too; `switchTo:193/switchBackward:213` already call `window.scrollTo(0,0)`; `swipeMove:188` calls `scrollChrome.show()`; the §2 shared-clip-rectangle diagnosis is unanimously endorsed.

## Round 5 + rescoping decision (v5 → v6: scrap track-dest, migrate to per-panel internal scroll)

Full detail: `DV11-Audit-R5.md`. 2 PASS / 3 FAIL, all high confidence. The track-dest core and the `sourcePinned` deep-path gating are endorsed. The remaining defects are all on the source pin: cross-branch reversal leaks `sourcePinned` onto the deep path (a forward tab-slide that reverses into a deep back-swipe - BLOCKING, auditor 4); boundary→reversal leaves `sourcePinned` unset (auditors 2, 3); the §6.2 source-pin test is not capturable with the back-to-back touchMove harness (auditors 3, 5); the §6.3(b) overlay-not-clipped assertion is false (the overlay IS clipped today, auditor 5); the commit-jump is NEW and unbounded (auditors 4, 5).

**Root observation.** Every R3-R5 blocker is on the source pin, which exists only because the track-dest approach changes the viewport height mid-gesture. The source-side jump is irreducible under any single viewport whose height changes (entry-jump without a pin, commit-jump with one); avoiding both needs a release hook the pager lacks. Track-dest is the wrong approach: it preserves the window-scroll rest model and tries to fake correct behaviour during the swipe, which spawns the pin and its edge cases.

**Process corrections during the loop.** R1 was re-run open-ended after the author seeded auditors with a leading prompt (the `audit-prompts-open-ended` principle). v4 dropped the plan's §8 "Audit points" section and the round prompt's prior-round context after the user flagged both as steering the audit. R4 (the first fully clean round) is what surfaced the deep-path viewport leak that the steered rounds missed.

**Rescoping decision (v6), author's call.** Scrap track-dest and the source pin entirely. Migrate `MobileTabPager` to the per-panel internal-scroll model that `GesturePageLayout` already uses on every deep-page route: a screen-height viewport (`html.fixed-viewport` + `height: 100%; overflow: clip`) with each panel a full-height independent scroller (`height: 100%; overflow-y: auto`). The viewport height is constant, so there is no dest clip and no source jump - both reported defects and the entire R3-R5 defect surface are deleted by construction. Remove `panelHeights`/`measureTab`/`neighborOffset`/content-height-sizing; migrate the `(tabs)` `window.scrollY` snapshot to per-panel `pageScrollStore` capture/restore (the GPL `:286-320` pattern); register the active panel via `scrollChrome.setScrollContainer`. Net code is simpler. Trade-off: tab routes lose native window-scroll (address-bar auto-hide, OS pull-to-refresh) - the same trade-off every deep-page route already makes, so the mobile app becomes consistent. v6 is audited under the same clean open-ended process.

## Round 7 + rescoping decision (v7 → v8: add the shared ownership layer)

Full detail: `DV11-Audit-R7.md`. 5/5 FAIL, all high confidence. **First unanimous endorsement of the architecture:** the unification onto the single `fixed-viewport` + `.scroll-pane` + `pageScrollStore` + `setScrollContainer` height/scroll model is correct; no second height mechanism survives. v7 over-promised "one abstraction, no special-casing" - the failures are concrete edits plus one real coordination-design gap.

Convergent blockers/majors:

The pager and GPL both touch the globals; `/discussion` is a sibling route, so a `/`↔`/discussion` SPA swap races their mount/destroy. v7's "refcount or querySelector" was an unresolved either/or.
- **Viewport missing `position: relative`** (auditors 1, 4) - the overlay anchor.
- **`measureViewportWidth`/`viewportWidth` must survive** (auditor 5) - feeds the indicator.
- **`listScroll` is dead** (auditors 2, 3, 4) - v7 hedged ("verify and remove if dead").
- **`data-tab-panel`→`data-preview-tab` rename breaks sibling specs** (auditor 3).

**Root insight:** unifying the _height model_ is necessary but not sufficient - the pager and GPL also both OWN the global `html.fixed-viewport` class and the `scrollChrome.containerEl` singleton, and two direct owners race across the route swap. v7 left that ownership duplicated.

**Rescoping decision (v8): add the shared ownership layer.** Factor ownership into shared primitives so each layout is a CLIENT, not a competing owner: (a) a new `viewport-lock` refcount module (`acquire`/`release`, class present while any layout holds it - ordering-independent); (b) `scrollChrome.releaseContainer(el)` - a conditional clear used in cleanup instead of `setScrollContainer(null)`, so a stale teardown never clobbers the new owner. Both the pager and GPL use them (GPL's edit is behavior-preserving for its single-owner steady state). Tighten every concrete edit: tab panels are bare `.scroll-pane[data-preview-tab=<key>]` with NO `.gpl-card` (keep `data-tab-panel` too, so sibling specs don't break); active panel also `.detail-scroll-pane`; viewport `height:100%; overflow:clip; position:relative`; track `h-full`; keep `measureViewportWidth`'s `viewportWidth`, strip only `neighborOffset`/`resetViewportScroll`/window-scroll listener; fix the deep-preview overlay anchor; `listScroll` removed definitively (dead); surgical removal of only the `.gpl-preview-pane` mirror rules (keep `.back-chip-overlay`). The height model + ownership are now genuinely one abstraction.

Verified-TRUE facts added (R7): the unification holds for height/scroll (no second mechanism); `app.css:333-341` `data-preview-tab` overrides `.scroll-pane` to flat-white for the three tab keys (no `.gpl-card` needed); the active panel carries both `.scroll-pane` and `.detail-scroll-pane` (GPL `:992`), `data-preview-tab` specificity wins; `listScroll` is dead (snapshot plumbing only, never applied to DOM); `/discussion` is a sibling top-level route so the swap unmounts `(tabs)` and mounts GPL (both touch the globals); `setOverride` (nested SearchScopePager) vs `setScrollContainer` (top-level) is the correct API split; `getCurrentScrollY` first-match is unambiguous at steady state and in `beforeNavigate`.
