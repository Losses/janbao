# DV11 - Unify MobileTabPager onto the Shared Scroll-Pane Height Model

**Status:** DRAFT v15 (pending plan audit). v14 reached 4/5 PASS; the lone FAIL (auditor 5, BLOCKING) was a doc slip: the §5 spec-rewrite bullet still said "scroll the active `.detail-scroll-pane`" on `/`, but v14 removed `.detail-scroll-pane` from the pager (§6.3/§6.4(b) correctly use `section[data-tab-panel=…]`). v15 corrects that selector, adds the missing setup-step note for the `swipe-forward-back-deep-page` no-top-flash test (its `window.scrollTo(0,600)` seed is also a no-op under `fixed-viewport`), and softens the "sole writer" rationale (GPL left/right also write the tab-href keys on deep routes, but never concurrently with the pager). See `docs/DV11-Meeting/DV11-Audit-R1.md`…`DV11-Audit-R14.md`.
**Scope:** Mobile only. Desktop renders each route's own page - unchanged.
**HEAD at authoring:** `6a35937`.

## 1. Goal

Eliminate the reported defect (revealed tab neighbour clipped/gapped because the viewport is pinned to the source panel's content height) by making the tab pager use the same per-panel internal-scroll height model as the deep-page layout, with a shared ownership layer so the two route-layouts never race on the global state that model depends on.

## 2. Root cause (verified R1-R11)

`MobileTabPager.svelte:302` `viewportHeight = panelHeights[activeIndex]` + `overflow-hidden` viewport pins the viewport to the active panel's content height mid-drag. The pager was built outside the deep-page scroll-pane abstraction (`MobileTabPager.svelte:454` scoped-CSS mirror). The fix: join the one abstraction GPL defines.

## 3. The single abstraction - height model + ownership layer

**Height model (one):** `html.fixed-viewport` + screen-height (`height: 100%; overflow: clip; position: relative; touch-action: pan-y pinch-zoom`) viewport + `h-full` track of `.scroll-pane` panels (`height: 100%; overflow-y: auto; overscroll-behavior-y: contain; -webkit-overflow-scrolling: touch; touch-action: pan-y pinch-zoom`), the active panel also `.detail-scroll-pane`; per-panel `pageScrollStore`; the active panel drives hide-on-scroll. `app.css:333-341` already styles `.scroll-pane[data-preview-tab="discussions|activity|messages"]` (flat-white + header padding) - the tab surface is pre-provided, NO `.gpl-card`.

**Ownership layer (shared):**
- `viewport-lock` refcount module: closure `$state` counter, clamped at 0; `acquire()` adds `html.fixed-viewport` at 0→1; `release()` removes at 1→0. Each caller tracks its own per-instance `held` flag (acquire on `!held → mobile`, release on `held → desktop`, release on cleanup if `held`); the pager (mobile-only) uses plain mount/destroy. `import.meta.hot?.dispose` removes the class AND zeroes the counter.
- `scrollChrome.releaseContainer(el)`: `if (containerEl === el) setContainer(null)`. Both layouts use it for cleanup; the destination's mount-`$effect` re-sets `containerEl` (self-heal). `setOverride` (the nested `/search` case) is UNCHANGED - separate slot, never co-mounted with the pager.

## 4. Target: the pager joins the abstraction

- `MobileTabPager.onMount` (mobile): `viewportLock.acquire()`; `onDestroy`: `viewportLock.release()` (browser-guarded).
- Viewport (`:364`): `height: 100%; overflow: clip; position: relative; touch-action: pan-y pinch-zoom` (REMOVE the `overflow-hidden` Tailwind class from `:365`, which conflicts with the inline `overflow: clip`; KEEP the `mobile-tab-pager-viewport` class - `app.css:322` keys off it). Track (`:371`): add `h-full`.
- Each section (`:375/390/407`): `class="scroll-pane h-full w-1/3 shrink-0"` + `data-tab-panel={MOBILE_TABS[N].labelKey}` (KEPT - identity + e2e + how the active panel is located for `setScrollContainer`/tests) + `data-preview-tab={MOBILE_TABS[N].labelKey}` (NEW - the sole reason is `app.css:333-341`'s flat-white surface, which matches the literal labelKey strings `discussions|activity|messages`). The active section is identified by `N === activeIndex` (NOT by a `.detail-scroll-pane` class - see below). Inline `overflow-y: auto; overscroll-behavior-y: contain; -webkit-overflow-scrolling: touch; touch-action: pan-y pinch-zoom`. Drop `p-3` and `translateY(neighborOffset)`. `bind:this` per section (array). REMOVE the three `use:measureTab={N}` directives (the action is deleted).
- **The active panel does NOT carry `.detail-scroll-pane`** (v14 change). Rationale: `.detail-scroll-pane` is the selector GPL-side consumers use to find the GPL centre - the e2e samplers `captureEnterAnimation`/`captureExitPreview` (`helpers.ts:260/482`), the discussion page's scroll reads, and the root-layout `getCurrentScrollY()` capture. Reusing it on the pager collided with all of them (R13 B1/B2). The pager does not need it: `hide-on-scroll` uses `setScrollContainer(activeSectionEl)` directly (no marker), and the per-panel `onscroll` capture is the sole writer for pager-route keys (the root capture is skipped - below). So `getCurrentScrollY()` is never called on a tab route, and the e2e samplers never latch a pager track.
- **Per-panel `pageScrollStore`, each panel keyed by its OWN tab href `MOBILE_TABS[N].href`** (NOT the global `page.url.pathname`). Each section's `onscroll` captures `pageScrollStore.capture(MOBILE_TABS[N].href, el.scrollTop)` (mirroring GPL's per-panel onscroll `:961-965/1005-1009`); an `$effect` keyed on `activeIndex` restores the active section's `scrollTop` from `pageScrollStore.get(MOBILE_TABS[activeIndex].href)` - sync-set then rAF-re-apply (mirrors GPL `:286-296`, avoids a top-flash). The key is index-derived, so it does NOT lag `activeIndex` during a programmatic tab switch. The root-layout `beforeNavigate` capture (`+layout.svelte:65`) is SKIPPED for pager routes (§5), so the pager's `onscroll` is the sole writer for the three tab-href keys - no clobber, no value lag.
- Active panel drives hide-on-scroll: an `$effect` keyed on `activeIndex` calls `scrollChrome.setScrollContainer(activeSectionEl)` (the active section, located via the bound `sectionEls[activeIndex]`); cleanup `scrollChrome.releaseContainer(activeSectionEl)`.
- Deep-preview overlay (`:426-437`): `top: 0; height: 100%` (containing block is the transformed `h-full` track). KEEP `scroll-pane` on the overlay (load-bearing for `app.css:325` header offset under `fixed-viewport`); remove ONLY the dead `gpl-preview-pane` class; keep `.gpl-card` + `.back-chip-overlay`.
- Delete: `panelHeights`/`measureTab` (`:301/314-322`) + the three `use:measureTab` directives, `neighborOffset` (`:309/332`) + its `translateY` + window-scroll listener, `viewportHeight = panelHeights[activeIndex]` (`:302`), `resetViewportScroll` (`:341-344`; flag: removes a defense-in-depth guard - the new `overflow: clip` viewport is not a scroll container, and no tab panel uses `scrollIntoView`), the dead `window.scrollTo(0,0)` in `switchTo`/`switchBackward` (`:193/213`), and the `.gpl-preview-pane` mirror rules (`:457-465`; KEEP `.back-chip-overlay` `:468-475`). KEEP `measureViewportWidth`'s `viewportWidth` + ResizeObserver (its remaining body is width-only: read `node.clientWidth` on init + ResizeObserver, no scroll listener, no `neighborOffset`, no `resetViewportScroll`); `viewportWidth` feeds `fractionalIndex` → the MobileTabBar indicator.
- **Behaviour delta (explicit):** switching to a previously-visited tab now RESTORES its saved scroll (per-panel `pageScrollStore`), not lands at top. Matches deep-page behaviour; intended (§6 pins it).

## 6. Tests

### 6.1 Height / clip (existing spec, flipped green, concrete metric)
REPLACE the tautological `vpHeight`-equality assertions (`:177-185`, both sides become screen height post-fix) with: each section `clientHeight === viewport height` (full-height scroller); AND a concrete internal-scroll reachability probe - `el.scrollTo(0, el.scrollHeight); assert el.scrollTop > 0` on the dest section (its content is reachable by internal scroll, NOT clipped by a shorter viewport) - since the existing `panel()` helper only measures `offsetHeight`/`getBoundingClientRect`, which cannot prove reachability. The back case `duringBack.panels.activity.bottom` reaches the viewport bottom (activity scrolls internally). The reachability probe is the load-bearing post-fix assertion.

### 6.2 Per-panel + cross-route scroll restoration; tab-switch restores; no top-flash
Scroll a tab panel, switch away and back → `scrollTop` restored (NOT reset to top), with NO transient wrong-panel jump mid-slide (the §4 index-derived key). Cross-route: scroll `/`, go to a thread, swipe back → discussions panel + thread GPL left preview restore from `pageScrollStore.get('/')` with NO top-flash (sync-first `$effect`).

### 6.3 Hide-on-scroll on the active tab panel
Scroll the active panel (located via `section[data-tab-panel=<activeLabelKey>]`, NOT `.detail-scroll-pane`) → Header hides/reveals.

### 6.4 Ownership coordination across the swap (EMPIRICAL, observable)
A `/`↔`/discussion` SPA nav, sampled every animation frame:
- (a) **`html.fixed-viewport` no-flicker - ARBITRATED, not asserted.** The swap is two-sided; Svelte does not guarantee mount-before-destroy, so a 1→0→1 transient is possible. The sampler REPORTS whether the class is ever absent for a painted frame. IF it is, the mitigation is a microtask-deferred removal at 1→0 (re-check the counter is still 0 before removing). The plan does not assume no-flicker; the test decides.
- (b) **Container is the destination's live panel - asserted via effect, scoped past the freeze.** Scroll the destination's active panel (located via its `data-tab-panel` attribute, NOT `.detail-scroll-pane`) AFTER `releaseNavigation` (the `/discussion`→`/` direction holds the Header via `holdThroughNavigation` until `(tabs)/+layout.svelte:113`; assert the forward `/`→`/discussion` direction, or the reverse after release) → the Header `translateY` responds.

### 6.5 `.appbar-title` never on tab roots
`/`, `/activity`, `/messages/inbox` do not carry `.appbar-title` (so `app.css:166` is a no-op on tabs despite Activity/Messages panels containing `.page-title`).

## 7. Risks

- **Refcount swap flicker (two-sided).** The §6.4(a) sampler arbitrates; mitigation (microtask-deferred 1→0 removal) if a flicker is observed. The `held`-guard + clamp cover GPL's resize-toggle and the pager's mount/destroy.
- **Scroll-chrome ownership.** Both layouts use conditional `releaseContainer`; the destination re-sets on mount (self-heal); `setOverride` unchanged, never contends. §6.4(b) pins it (scoped past the freeze).
- **`.page-title` on tabs** - no-op only because tab roots routes lack `.appbar-title` (§6.5).
- **`.detail-scroll-pane` collision** - eliminated in v14: the pager's active panel does NOT carry the marker, and the root capture is skipped on pager routes, so `getCurrentScrollY()`/`captureEnterAnimation`/`captureExitPreview`/the discussion page never see a pager panel. There is no `.detail-scroll-pane` on a tab route (it appears only when GPL mounts on a deep route), so there is no first-match ambiguity during the `/`↔`/discussion` swap either.
- **`/` (locked) ↔ `/discussions/pN` (window-scroll) boundary at pagination** - a NEW discontinuity the plan INTRODUCES (today both are window-scroll; the plan locks `/` only). `/discussions/pN` is a separate non-pager route, unchanged; the boundary is out of scope but is a real new edge, not "no worse than today."
- **Native window-scroll loss on tab routes** - the same trade-off every deep-page route makes.
- **Net code smaller.** Deletes a private height model + a CSS mirror + a dead store; adds one small refcount module + one store method.
