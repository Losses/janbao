## Blocking issues (deduplicated)

**A1 - Family B (list <-> thread/conversation) scale animation is not delivered (HIGH, 5/5).** The layer's `fabConfig` returns `null` on overlay routes (`isOverlayRoute(page.url.pathname)` short-circuits the resolver at `FloatingActionButtonLayer.svelte:98`), so the FAB atom unmounts the instant the pathname swaps to `/discussion/<id>`. Result: the FAB pops instantly to scale 0 instead of scaling out over the first 50% of the slide (forward) / scaling in over the last 50% (back-swipe). Plan §4.3 Family B, §4.4, §6.5, §6.6, §7 require this scale animation; the implementer self-flagged the deviation in the journal's "Deviations from the plan" section and rewrote the e2e `REGRESSION` spec to cover only Family A (tab swipe), where the source route stays a list route during the drag and the scale-out IS observable.

The sampler math (`fractionFromSample`) and the track-store wiring (`active-gesture-track.svelte.ts`, the `bind:this={trackEl}` + `setActiveGestureTrack`/`clearActiveGestureTrack` in `MobileTabPager.svelte` and `GesturePageLayout.svelte`) are ALREADY in place. Only the route gate prematurely nulls the config, and the Family B fraction math collapses to `tabFraction(sample, tabIndex)` which is mathematically correct for discussions (tabIndex 0) but stays clamped at 0 for messages (tabIndex 2) because the GPL renders two panels (left preview + center thread) for these routes, so `pxToFraction` reaches 1 at rest regardless of `centerTab`.

**Family C - compose routes use instant unmount instead of the plan's P2 CSS transition (HIGH, 1/5 blocking).** `/post/discussion` and `/messages/new` reach `fabConfig === null` (same short-circuit), so the atom unmounts instead of easing scale 1 -> 0 over 200ms via the plan's §4.9 `transition: transform 200ms ease-out`. Four of five reviewers accept the unmount (plan §6.2: "each transition independently satisfies the symmetric model"), but Reviewer #1 holds the line on the missing 200ms ease. Fixing it properly is strictly better than the unmount deviation and removes the only dissenting vote.

## Deviation assessment (mostly ACCEPTABLE)

- **Family C unmount (vs plan §4.9 P2 CSS transition).** Deviation REJECTED by Round-1 (1/5 blocking); the revision implements the plan's CSS transition.
- **`fab-scale.svelte.ts` store dropped (vs plan §4.6).** ACCEPTABLE. The layer is the sole reader/writer of the sampler output; component-local `$state` is sufficient for a single layer instance. Re-introducing a store would add a thin reactive holder with one consumer. The plan's §4.6 described it as "thin" and the deviation is faithful to the singleton-layer reality.
- **`active-gesture-track` module fallback set unconditionally (vs plan §4.5 mirroring `setContext`).** ACCEPTABLE. The consumer (the FAB layer in AppShell) is an ANCESTOR of the track-owning descendants; Svelte context flows parent -> child only, so `getContext` cannot reach upward. The unconditional module fallback is the only SSR-reachable channel; the `$state` is `null` on the server and the writers only run in browser `$effect`/`onDestroy`, so the unconditional fallback has no SSR side effect.
- **FAB positioning on the atom, not the layer (vs plan §4.8).** ACCEPTABLE. The atom carries `position: fixed` with `right`/`bottom` insets; the layer is a non-positioned wrapper that gates viewport (`md:hidden`) and stacking (`z-35`). This keeps the atom self-contained and avoids the layer establishing a containing block that would interfere with `position: fixed` under `html.fixed-viewport`.

## Revision decisions

1. **Family B - keep the FAB atom mounted on overlay routes, driven by the GPL track sampler.** `fabConfig` resolves the SOURCE LIST's FAB on overlay routes (`/discussion/*` -> discussions; `/messages/[id]` -> messages) instead of returning null. foregroundFraction rests at 0 on the overlay (the thread covers the list -> scale 0 -> invisible, `pointer-events:none`, `aria-hidden`; this also satisfies the deep-link no-flash requirement). During the transition the GPL track sampler drives foregroundFraction via `listForegroundFromThreadCover(pxToFraction(m41, panelWidth)) = 1 - threadCoverProgress` (forward enter 1 -> 0; back-swipe 0 -> 1). The collapsed `tabFraction(sample, tabIndex)` math is replaced with the dedicated Family B helper because the messages route (tabIndex 2) would otherwise stay clamped at 0 (the two-panel GPL track reaches `pxToFraction = 1` at rest regardless of `centerTab`).
2. **Nav-moment flash hazard.** At the swap instant the destination GPL has not bound its track / started animating, so the resting 0 would flash the FAB to scale 0 before the sampler takes over. The revision adds a `forwardNavHoldoverActive` derivation: while `fabConfig.family` is overlay/compose AND the sampler has not yet published its first sample AND (`navStore.direction === 'forward'` OR `navStore.navInFlight`) AND no chip-exit is active, foregroundFraction holds at 1. On a deep-link (no forward nav in flight) the holdover is false and the resting 0 applies, so there is no flash of scale 1 on the deep-linked overlay. The `samplerHasPublished` latch resets at each fresh `startSampler` arm, so a route swap that unbinds and rebinds the track earns a new holdover window.
3. **Family C - keep the atom mounted on compose routes, eased by a CSS transition.** `fabConfig` resolves the SOURCE LIST's FAB on compose routes (`/post/discussion` -> discussions; `/messages/new` -> messages) at foregroundFraction 0 rest. The atom gains `transition: transform 200ms ease-out`, active only when a `transitionEnabled` prop is true. The layer sets `transitionEnabled = !samplerActive && !pager.dragging && !forwardNavHoldoverActive` so Families A/B stay continuous via the per-frame sampler (no second unsynchronized clock fighting the track's CSS easing) while Family C's discrete route-predicate flip eases over 200ms.
4. **Unified resting model.** foregroundFraction resting default = 1 on list routes (`/`, `/messages/inbox`), 0 on overlay + compose routes; the sampler overrides during transitions; the CSS transition eases discrete (Family C) changes but is suppressed during continuous (Family A/B) sampling.
5. **Tests.** Restore the plan §7 Family B/C e2e specs in `e2e/fab.spec.ts`: Family B forward (tap a discussion card; sample FAB scale across the ~200ms snap; assert first scale ~1, min scale < 0.5, last scale < 0.1); Family B back (swipeBack thread -> list; assert first scale < 0.2, max scale > 0.5, last scale > 0.9); Family C forward (tap FAB -> `/post/discussion`; assert sampleCount > 2, first scale ~1, min scale < 0.15); Family C back (compose -> list via history back; assert sampleCount > 2, first scale < 0.2, max scale > 0.5). The two superseded "no FAB on thread/compose route" specs become "FAB rests at scale 0 on a deep-linked thread/compose route (no flash of scale 1)". Keep the existing Family A / scroll-hide / pointer-events / route-gating / tap-navigates specs.
6. **Comment leak + journal.** Reword the two "FAB" comments in `MobileTabPager.svelte:77` and `GesturePageLayout.svelte:256` to generic gesture-surface references. Correct the journal's `bun run lint` EXIT 0 claim to state the pre-existing `app.css` exit-1 accurately (eslint clean, similarity-ts type-duplicates 0).
